### Why PSI is the smoking gun

- `full avg10=91.64` means ~92% of the time, **every** non-idle task was simultaneously blocked on I/O.
- PSI `total` for I/O ≈ 3.46e9 µs ≈ **58 minutes of accumulated stall** on a box that had been up ~66 minutes.
  It has been like this almost since boot.
- Memory pressure = 0 → rules out swap death / RAM thrash. This is purely block-I/O.
- Load 14 on 16 threads ≈ 14 tasks sitting in D-state — exactly the D-state pileup an I/O-wedged system shows.
- Cached pages worked (binaries already in RAM: `date`, `seq`, `grep`, `ps`, `pkill`; procfs/sysfs reads all fine).
  Uncached pages required a block read → hang. Consistent with the drive/controller answering nothing.

### What this is NOT

- Not my commands: the load was already 11.68+ **before** any script of mine reached a disk-touching section
  (my first script hung before `nvme list` ever ran).
- Not memory exhaustion (PSI memory = 0).
- Not an SSH/transport artifact (`seq` streamed 4KB fine in the same session type).
- Not a PS5 firmware problem: Linux runs entirely from its own medium; the internal SSD/PS5-OS was never
  mounted or touched.

## Leading hypotheses (ranked, all testable next boot)

1. **NVMe APST / power-state bug** — drive drops into a deep power state and the controller fails to wake.
   Classic on consoles/odd hosts: each I/O eats a 30s timeout, I/O stall ~90%+, load pileup.
   Fix: kernel cmdline `nvme_core.default_ps_max_latency_us=0`. Signature in `dmesg`: repeated
   `nvme nvme0: I/O ... timeout, aborting` / `resetting controller`.
2. **Drive thermal throttling** — bare drive or bad heatsink contact in the M.2 bay. Signature: temp ≥ ~70-80°C
   with `percentage_used` fine and no reset spam. Fix: heatsink/airflow.
3. **Failing / fake-medium** — dying USB stick, dead-ish NVMe (check SMART: `media_errors`, `critical_warning`).
   Signature: I/O errors in dmesg, ext4/btrfs errors.
4. **PS5 M.2 slot power marginality with a power-hungry drive** — controller drops under load.
   Same signature as (1) but correlated with load; fix = a more efficient drive.

All four are **boot-medium problems, not PS5 problems**. Worst case we re-flash ChimeraOS to a different
drive — zero firmware risk.
